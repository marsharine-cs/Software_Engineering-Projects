CASE STUDY · FULL-STACK APPLICATION

Student Progress Tracker

A secure, database-backed classroom application that preserves assessment history and gives teachers a current view of student mastery.

THE PROBLEM

Student information becomes fragmented.

Teachers often combine rosters, skill lists, assessment records, and current mastery judgments across separate documents. That makes it difficult to answer a simple question quickly: what is each student’s latest demonstrated status for each skill?

THE SOLUTION

One workflow for records, history, and current status.

I built an authenticated application where a teacher can manage students and skills, record dated assessments, review assessment history, and view each student’s latest mastery status in a single dashboard. Password recovery and protected application access support the complete account workflow.

  • Create, edit, and remove student and skill records.
  • Record assessments without erasing earlier evidence.
  • Review dated assessment history.
  • Calculate and display the latest status for every student-and-skill pair.

MY ROLE

Product definition through production verification.

I designed and implemented the application, relational data flow, interface states, authentication behavior, tests, and deployment. I organized the work through GitHub Issues, feature branches, and pull requests so each feature could be developed and verified incrementally.

ENGINEERING HIGHLIGHTS

Evidence beyond the interface.

Full-stack data flow

React and TypeScript components read and write student, skill, and assessment data through Supabase. The PostgreSQL model maintains relationships among those records while the dashboard combines them into a current classroom view.

Authentication and authorization

The application manages Supabase sessions, protected access, password recovery, and Row Level Security so authenticated users can work with only the data allowed by database policy.

Testing and quality

Vitest and React Testing Library cover key component behavior. TypeScript checks, ESLint, production builds, and manual verification support the release workflow.

TECHNICAL DECISION

Preserve history; calculate the present.

I chose to store dated assessment events rather than overwrite a single current-status field. The dashboard then selects the latest relevant record for each student-and-skill pair.

This design preserves the evidence behind the current status, supports progress review over time, and leaves room for future reporting without sacrificing a fast dashboard view.

PRODUCTION CHALLENGE

A working local build still has to survive deployment.

A production issue exposed a Vite environment-configuration problem. I traced the failure to how client-side environment variables were configured, corrected the deployment settings, and reverified the authentication flow in production. The lesson was practical: a successful local build is only one part of shipping; the deployed environment must be treated as its own test condition.

RESULT

A credible, complete application workflow.

The result is a deployed full-stack application with authentication, relational data, history-aware business logic, CRUD functionality, a teacher-facing dashboard, and automated tests. It demonstrates my ability to move from a real user problem to working software and to troubleshoot what changes in production.

NEXT ITERATION

What I would build next.

  • End-to-end tests for authentication and core teacher workflows.
  • Role-based permissions for multiple school users.
  • CSV import, export, and progress-report generation.
  • Expanded audit history and dashboard filtering.
